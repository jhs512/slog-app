# 홈 전용 광고

## 원인과 수정

광고 슬롯은 홈과 글 목록에 있었고, AdSense 스크립트는 공통 루트 레이아웃에 있었다. 따라서 슬롯이 없는 상세 페이지에도 광고 런타임이 실행됐다. 홈에서 클라이언트 탐색으로 이동해도 같은 문서의 광고 코드와 자동 광고 DOM이 남을 수 있었다.

홈 `/`는 `(home)` 루트 레이아웃에서만 광고 스크립트를 로드한다. 상세·목록·설정 등 나머지 페이지는 `(site)` 루트 레이아웃을 사용한다. 목록의 광고 슬롯은 제거했다. 홈의 광고 슬롯 ID, 반응형 형식, 운영 모드 제한은 그대로다.

[Next.js의 여러 루트 레이아웃](https://nextjs.org/docs/app/api-reference/file-conventions/layout)은 그룹 사이의 이동을 전체 문서 로드로 처리한다. `<Link>`로 홈에서 상세로 이동할 때도 이전 광고 런타임을 폐기하며, 홈으로 돌아오면 새 문서에서 광고를 초기화한다. 다른 페이지끼리의 클라이언트 탐색은 유지한다. 홈을 오가는 이동에는 전체 로드 비용이 추가된다.

## 검증

`AGENTS.md`의 홈 전용 광고 검증 명령으로 운영 빌드를 만든 뒤 `playwright.ads.config.ts`를 실행한다. 실제 광고 요청은 모의 응답으로 대체하고, 지속 실행되는 모의 자동 광고를 사용해 단순 슬롯 제거만으로 통과하지 못하도록 한다.

- 수정 전: 6개 검사 모두 실패. 상세 직접 진입과 홈 → 상세 이동에서 광고 스크립트가 남는 것을 재현했다.
- 수정 후: 7개 검사 통과. 상세 2개·목록·개인정보·404 직접 진입과 PC/모바일 홈 → 상세 → 뒤로/앞으로 → 홈 이동을 확인했다. 상세에서는 광고 스크립트·슬롯·자동 광고 DOM·전역 런타임이 없다.
- 운영 빌드, TypeScript, ESLint 통과.
- 기존 렌더링 회귀 검사 34개 통과(만화·Mermaid·뷰어·읽어주기). 변경 파일 Prettier 검사와 Git 공백 검사도 통과.

광고 검사는 실제 광고 서버의 소재·수익·운영 계정 설정을 검증하지 않는다. GTM은 기존대로 유지했다. 공개 GTM 응답에서 발견된 `pagead2` 주소는 전환 측정 코드였고 AdSense 스크립트 문자열은 없었다.

## 운영 반영

main 푸시 시 기존 Vercel 연동이 프론트엔드를 자동 배포한다. GitHub 커밋 상태의 `Vercel` 성공과 해당 커밋의 Production 배포 성공을 확인한 뒤, `https://www.slog.gg`에서 홈의 광고 스크립트·슬롯과 상세의 광고 부재를 확인한다. PC/모바일 링크 이동, 뒤로/앞으로, 상세 직접 진입도 확인한다. 백엔드와 광고 계정 설정은 이번 수정 범위에 포함되지 않는다.
