# 기술 실험

## E1. 런타임 수명

매번 새 런타임을 만드는 방식과 컴파일러만 재사용하는 방식을 비교한다. 다시 열 때 원문·입력·출력·메모리 상태가 남지 않아야 하며 닫기/중지 후 실행 작업이 계속 살아 있지 않아야 한다. 초기화와 빠른 재실행을 동시에 만족하는지 실제 브라우저에서 확인한다.

## E2. C 메모리 추적

지역 변수, 배열, 포인터, 동적 할당, 해제를 포함한 실제 C 예제를 실행하고 메모리 추적값을 대조한다. 소스를 보고 추측한 애니메이션을 실제 메모리라고 표시하지 않는다. 브라우저 실행과 메모리 시각화의 검증 결과를 분리한다.

## E3. React 관찰 데이터

버튼 클릭으로 상태가 바뀌는 단일 파일 예제에서 렌더링 화면, 실제 DOM, React VDOM 패널이 서로 다른 데이터를 관찰하는지 확인한다. DOM을 복사해 VDOM이라고 표시하지 않는다. 관찰 방식이 React 내부 버전에 의존하면 킷 버전과 회귀 검사에 그 경계를 기록한다.

## E4. Rust·Go의 브라우저 컴파일

사용자가 추가로 명시한 실험이다. Rust와 Go의 소스 코드를 받아 브라우저 안에서 컴파일하고 결과까지 실행할 수 있는지 각각 검증한다. 서버 기반 온라인 컴파일러와 이미 빌드한 WASM 실행은 이 실험의 성공 조건이 아니다. 컴파일러·표준 라이브러리 다운로드, 격리·중지, 필요한 브라우저 기능과 단일 파일 예제 지원을 확인한다. 문서만으로 VERIFIED를 주지 않는다.

현재 E1~E4의 전체 제품 통합 결과는 NOT VERIFIED다. 후보 조사와 실제 실행 결과를 구분해 기록한다.
