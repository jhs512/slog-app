# 슬로그 브라우저 코드 실험: 합의 내용 확인

## 진입과 수명

- 작성자가 명시한 실행용 코드 블록에만 오른쪽 위 재생 버튼을 표시한다.
- 같은 페이지의 레이어 팝업을 열며 새 창으로 이동하지 않는다.
- 문서의 코드로 시작하고 처음 열 때 한 번 실행한다.
- 팝업 안에서 임시로 코드를 수정할 수 있고 이후에는 실행 버튼으로 재실행한다.
- 글 원문에 코드를 저장하는 기능은 없다. 닫고 다시 열면 원문 코드와 초기 실행 상태로 시작한다.

## 실행 범위

- 컴파일·실행·추적은 모두 브라우저에서 처리한다. 서버 실행과 외부 원격 실행 API는 사용하지 않는다.
- WebAssembly와 Web Worker를 활용한다. 해당 조건에서 지원할 수 없는 언어는 제외한다.
- Java·C·C++ 실행 시각화와 웹 실험 환경을 목표로 하며 JavaScript·TypeScript·Rust·Go도 브라우저 안에서 가능한 범위를 직접 검증한다. 아직 모든 언어 지원을 보장하는 상태가 아니다.
- 첫 버전은 단일 파일 예제다. 웹 예제는 HTML 안에 CSS와 JavaScript를 담을 수 있다.
- 프로그램 입력은 실행 전 선입력만 지원한다. 실시간 입력은 우선 시도하지 않고 후속 검토로 둔다.

## 패널

- 코드, 렌더링 화면, 실시간 DOM, React VDOM, 메모리 시각화, 콘솔, 입력은 각각 독립 패널이다.
- 언어와 스타터킷에 맞는 패널 조합을 제공하고 전부 동시에 사용하도록 강제하지 않는다.
- C 예제는 코드 편집기와 메모리·콘솔·입력으로 구성할 수 있어야 한다.
- 레이아웃 선택, 패널별 표시 전환, 경계 핸들로 크기 조절을 지원한다.
- 화면 설정만 브라우저에 기억한다. 구체적인 기본 배치는 실제 화면 검토로 다듬는다.
- 웹 렌더링 화면의 기본 텍스트 글꼴은 Pretendard다. 콘솔과 코드 편집기에는 이 요구를 적용하지 않는다.

## 스타터킷

- 반복적인 환경 준비를 줄이기 위한 미리 정해진 실행 환경이다.
- 개발자인 사용자만 개발 코드로 추가·수정한다. 별도 관리자 CRUD 화면은 만들지 않는다.
- React 기본 킷과 React+Tailwind 킷을 구분한다.
- 코드 펜스에 `react-starter-1`, `react-tailwind-starter-1`처럼 킷 이름과 버전을 적는다.
- 기존 버전 수정과 새 버전 추가가 모두 가능하다.
- 글은 선택한 버전을 계속 사용한다. 그 버전의 수정은 반영하되 새 버전으로 자동 전환하지 않는다.

## 다음 단계

사용자는 이 정리에 동의하면서 웹 렌더링 화면의 Pretendard 기본 글꼴을 추가했다. 공통 이해 확인을 마쳤다. 민수가 직접 PStack poteto-mode로 브라우저 런타임의 실제 지원 범위와 시각화를 검증하고 설계·구현한다. 다른 에이전트나 철수에게 이 기능의 담당을 넘기지 않는다.
