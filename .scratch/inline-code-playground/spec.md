# 슬로그 브라우저 코드 실험

Status: ready-for-agent

## Problem Statement

독자가 수업 문서의 코드를 실험하려면 문서를 떠나 별도 실행 환경을 준비해야 한다. 작성자는 반복되는 React 환경 설정을 예제마다 설명해야 하고, 독자는 실행 결과와 DOM·메모리 변화를 함께 관찰하기 어렵다.

## Solution

작성자가 실행용으로 지정한 코드 블록에만 우측 상단 재생 버튼을 제공한다. 버튼은 같은 페이지의 레이어 팝업을 열고 원문 코드를 한 번 실행한다. 독자는 팝업에서 임시 수정하고 수동 재실행하며, 렌더링 결과와 서로 다른 시각화 패널을 선택해 관찰한다. 컴파일·실행·추적은 모두 브라우저 안에서 수행한다.

## User Stories

1. 작성자로서 실행용 코드 블록을 명시하여 불완전한 설명용 코드에는 재생 버튼이 생기지 않기를 원한다.
2. 독자로서 코드 블록 우측 상단에서 실행을 시작하여 문서를 떠나지 않고 실험하고 싶다.
3. 독자로서 새 창 대신 레이어 팝업을 열어 읽던 문맥을 유지하고 싶다.
4. 독자로서 팝업을 열면 원문 코드가 한 번 실행되어 결과를 즉시 보고 싶다.
5. 독자로서 코드를 임시 수정하고 실행 버튼으로 재실행하여 변화를 비교하고 싶다.
6. 작성자로서 독자의 실험이 게시글 원문에 저장되지 않기를 원한다.
7. 독자로서 팝업을 다시 열면 원문 코드와 초기 입력·출력·추적 상태로 시작하고 싶다.
8. 독자로서 프로그램 입력을 실행 전에 여러 줄로 미리 작성하고 싶다.
9. 독자로서 코드·웹 렌더링·실시간 DOM·React VDOM·메모리·콘솔·입력을 각각 독립 패널로 사용하고 싶다.
10. 독자로서 언어에 필요한 패널만 열어 불필요한 화면을 줄이고 싶다.
11. C 학습자로서 코드·메모리·콘솔·입력만으로 실행을 관찰하고 싶다.
12. 웹 학습자로서 실제 렌더링과 실제 DOM 변화를 서로 다른 패널에서 보고 싶다.
13. React 학습자로서 React 렌더 트리와 실제 DOM을 구분해 보고 싶다.
14. 독자로서 패널을 개별적으로 열고 닫고 배치를 선택하고 싶다.
15. 독자로서 경계 핸들을 끌어 패널 크기를 조정하고 싶다.
16. 독자로서 같은 브라우저에서 패널 배치·크기·열림 상태를 기억하고 싶다.
17. 작성자로서 단일 파일 예제로 복잡한 프로젝트 준비 없이 수업을 구성하고 싶다.
18. 작성자로서 React 기본 킷과 React+Tailwind 킷을 구분해 선택하고 싶다.
19. 개발자로서 스타터킷을 소스 코드로만 추가·수정하고 싶다.
20. 개발자로서 기존 킷 버전을 수정하거나 새 번호 버전을 추가하고 싶다.
21. 작성자로서 선택한 버전의 수정은 받되 새 버전으로 자동 전환되지 않기를 원한다.
22. 웹 학습자로서 렌더링 화면의 기본 글꼴을 Pretendard로 보고 작성한 CSS로 재정의하고 싶다.
23. 독자로서 실행을 중지하고 팝업을 닫아 무한 실행이나 이전 실행의 영향을 제거하고 싶다.
24. 독자로서 지원하지 않는 언어·킷·버전이나 컴파일 실패를 명확히 이해하고 싶다.
25. 개발자로서 Java·C·C++·JavaScript·TypeScript·Rust·Go의 브라우저 실행 가능성을 실제 검증해 지원 범위를 정하고 싶다.
26. 독자로서 서버에 코드를 보내지 않고 소스 컴파일부터 실행까지 브라우저 안에서 처리하고 싶다.

## Implementation Decisions

- 공통 실험 작업공간과 언어별 실행 어댑터를 분리한다. 어댑터는 실행 결과와 제한된 추적 데이터를 제공하고, 작업공간은 독립 패널과 수명을 관리한다.
- 기존 Markdown 코드 블록 렌더러의 AST 정보로 실행용 표시를 판별한다. 일반 코드·Mermaid·기존 특수 블록의 처리를 보존한다.
- 스타터킷은 개발 코드의 레지스트리로 관리한다. React 기본 및 React+Tailwind를 별도 킷으로 두고 이름과 번호 버전을 참조한다. 같은 버전 수정은 참조 문서에 반영하고 새 버전 추가는 자동 이행하지 않는다.
- 최초 열기는 자동 실행, 수정 후에는 수동 실행이다. 닫기·재열기·문서 교체 시 이전 실행 및 추적 상태를 폐기한다. 런타임 재사용은 상태 누출이 없다는 실험을 통과한 경우에만 허용한다.
- 컴파일·실행·시각화 데이터 수집은 브라우저 안에서만 수행한다. 정적 런타임 다운로드는 가능하지만 원격 컴파일·실행 API와 실행 서버는 사용하지 않는다.
- 사용자 코드는 인증된 문서 화면과 격리한다. 메시지 경계를 검증하며 중지·시간·출력·추적량 제한과 정리를 제공한다. 호스트 앱 전체의 격리 헤더를 무작정 바꾸지 않는다.
- 첫 버전은 단일 파일과 선입력만 지원한다. 실시간 표준입력 구현을 우선 시도하지 않는다.
- 실시간 DOM, React VDOM, 메모리 시각화는 서로 다른 데이터와 패널이다. DOM을 복사해 VDOM이라고 부르거나 소스 추정치를 실제 메모리라고 표시하지 않는다. React 내부 자료 사용 시 버전 제약을 명시한다.
- 화면 설정만 로컬 저장하며 코드·입력·출력·실행 상태는 저장하지 않는다.
- 웹 렌더링에만 Pretendard 기본 글꼴을 적용한다. 편집기와 콘솔 글꼴은 이 요구에 포함하지 않는다.
- 언어 지원은 실험 결과로 결정한다. Rust·Go는 소스 컴파일부터 브라우저에서 검증해야 하며 미리 컴파일된 WASM 실행만으로 통과시키지 않는다. 불가능하거나 실용적이지 않은 언어는 근거와 함께 제외한다.

## Testing Decisions

- 가장 높은 공통 검증 경계는 실제 문서에 실행용 블록을 렌더링하고 재생→임시 수정→재실행→닫기→재열기를 수행하는 사용자 흐름이다. 기존 렌더링 회귀 검사 방식을 확장한다.
- 이 흐름에서 자동 최초 실행, 수동 재실행, 원문 보존, 상태 초기화, 독립 패널, 화면 설정 복원을 관찰한다. 내부 파일 구조나 함수 호출 순서를 테스트하지 않는다.
- 런타임별 별도 경계는 동일한 실행 계약에 소스·선입력을 주고 실제 출력·진단·추적 및 중지를 관찰하는 것이다. 컴파일러 재사용 격리, C 포인터·배열·할당/해제, React 클릭 이후 세 종류 화면의 차이를 실험한다.
- Rust·Go와 C++·Java 후보는 실제 브라우저의 네트워크 요청·컴파일·실행 증거, 지원 문법, 최초 다운로드 및 자산 크기, 라이선스와 제약을 기록한다. 검증 전 지원 완료라고 표시하지 않는다.
- 실행 실패·무한 루프·과다 출력·팝업 중간 닫기·오래된 결과 메시지·미지원 킷 버전을 검증한다.
- 기존 일반 코드, Mermaid, 중첩 상세, 만화/발표, 테마 및 문서 재렌더링을 회귀 확인한다. 키보드 진입·닫기·포커스 복귀와 패널 조절 접근성을 확인한다.

## Out of Scope

- 실행 서버와 외부 원격 실행 서비스.
- 실시간 표준입력, 여러 파일 프로젝트, 사용자 패키지 설치 및 게시글 원문 저장.
- 스타터킷 관리 CRUD 화면 및 일반 사용자의 킷 등록.
- 검증되지 않은 모든 언어의 지원 약속, 모든 시각화의 동시 사용 강제.

## Further Notes

- 사용자는 충분한 인터뷰 후 나머지 세부를 추천안에 맡겼으며 마지막으로 스펙·티켓 작성을 민수에게, 이후 구현을 클로드에게 맡겼다. 이전의 담당 위임 금지는 이 최신 지시로 변경되었다.
- 기존 연구는 후보 탐색 단계다. 종단간 런타임 실험은 아직 미검증이며, 벤더 코드와 의존성 준비를 완성된 기능으로 간주하지 않는다.
- 구현 인계는 implement-spec 절차를 따르며, 저장소의 로컬 이슈 트래커와 PR 없이 main에 통합하는 규칙을 따른다.
