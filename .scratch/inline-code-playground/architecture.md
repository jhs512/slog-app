# 설계 스케치

## 호출자가 사용하는 모양

1. 글의 명시적인 실행용 fence를 registry로 해석한다.
2. 버튼이 선택된 원문과 실행 정의를 공통 작업 공간에 전달한다.
3. 작업 공간은 실행 세션을 하나 만들고, 소스·선입력·상태·패널 설정을 관리한다.
4. 엔진은 브라우저 안에서 실행하고 제한된 데이터 이벤트만 작업 공간에 전달한다.
5. 독립 패널은 해당 이벤트의 데이터만 렌더링한다.
6. 닫으면 세션과 모든 실행 자원을 폐기한다. 다음 열기는 원문에서 다시 시작한다.

## 구조 후보

### A. 엔진별 전체 뷰어를 팝업에 삽입

기존 Java/C 등의 전체 앱을 직접 iframe으로 넣는 방식이다. 첫 연결은 짧지만 편집기·콘솔·입력·시각화 UI가 엔진마다 중복되고 패널별 조절과 초기화 계약을 통일하기 어렵다. 이 구조는 채택하지 않는다.

### B. 공통 작업 공간과 데이터 이벤트 기반 엔진

원문 해석과 작업 공간은 공통으로 두고, 실행 엔진을 adapter 뒤에 둔다. 출력·진단·DOM·React 트리·메모리 추적은 각각 별도 데이터로 전달한다. 독립 패널과 수명·설정 보존을 한 번만 구현할 수 있어 이 구조를 선택한다.

## 데이터 경계

- 실행 정의: 실행 fence, 언어, 킷 이름/버전, 가능한 패널 종류.
- 실행 요청: 원문 또는 실험 코드와 선입력 문자열.
- 실행 상태: 런타임 준비, 준비 완료, 실행 중, 완료, 오류, 중지.
- 패널 데이터: 콘솔 항목, 진단, DOM 트리, React 트리, 메모리 스냅샷. 하나의 시각화 HTML로 합치지 않는다.
- 화면 설정: 언어/킷에서 사용 가능한 패널에 대한 배치·크기·표시 상태. 코드와 실행 데이터는 저장하지 않는다.

## 실행 격리

사용자 코드는 글이 실행되는 인증된 문서 영역과 분리한다. Worker 또는 sandbox iframe 경계를 사용하고, bridge는 실행 데이터만 받는다. 브라우저 외부 컴파일/실행 API는 없다. 정적 런타임 자산 다운로드는 원격 실행과 구분한다.

## 미해결 기술 사실

- 실제 사용 가능한 엔진과 임베드/라이선스/의존 자산.
- C/C++와 Java의 일반 실행 및 메모리 추적 지원 범위.
- React 가상 DOM 패널의 관찰 데이터와 표현 범위. DOM 트리나 추측한 상태를 가상 DOM으로 오인해 표시하지 않는다.
- 초기 런타임 로딩·중지·시간 제한과 격리된 폰트/자산 로딩.

기술 검증 결과에 따라 이 문서의 계약을 갱신한다. 확인하지 않은 기능은 가짜 데이터로 채우지 않는다.
